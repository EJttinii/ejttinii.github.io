담당 업무
이용자에게 가는 공지, 메일, 알림이 제대로 작동하도록 기획

이용자와 직접 소통하는 일을 맡은 것은 아니었습니다. 대신 이용자가 받는 메시지가 어떤 상황에서, 어떤 내용으로, 어떻게 전달될지를 설계하는 쪽을 맡았습니다.

작업 히스토리

서비스가 완벽히 정리되지 않은 상태에서 이용자 소통을 기획하다 보니, 메인 컨셉부터 계속 바뀌었습니다. 그때마다 같은 작업을 다시 해야 했습니다.

이 상황에서 저는 바뀐 내용을 버전별로 기록하고, 왜 바뀌어야 하는지 이유를 정리하면서 일했습니다.

  1. v1

    서비스가 정리되기 전에 기획을 시작

    이용자 대상 공지·메일·알림 기획에 먼저 착수.

  2. v2

    메인 컨셉이 바뀜

    컨셉이 바뀌면서 이미 만든 기획을 다시 작업.

  3. v3

    변경 내용을 버전별로 기록

    무엇이 어떻게 바뀌었는지 한눈에 볼 수 있게 정리.

  4. v4

    변경 이유를 함께 정리

    왜 바뀌어야 하는지를 남겨, 바뀐 내용을 설명할 수 있는 상태로 일함.

실제 버전명, 날짜, 구체적인 변경 사례로 교체하면 더 설득력 있는 섹션이 됩니다.

나에 대하여

꼼꼼함

주변에서 꼼꼼하다는 이야기를 자주 듣습니다. 기획에서는 변경을 놓치지 않고 기록하는 방식으로 드러났습니다.
